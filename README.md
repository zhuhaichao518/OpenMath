# OpenMath

**给 LLM 一套可复用、可检索、可逐步补全的数学证明工具。**

[English](README.en.md) · [设计说明](docs/DESIGN.md) · [描述语言](docs/LANGUAGE.md) · [路线图](docs/ROADMAP.md) · [参与贡献](CONTRIBUTING.md)

> 一个数学命题，可能有很多条证明路线。有的路线只差一个引理，有的只差几步推导。OpenMath 希望保留这些路线、证据和缺口，让 AI 在已有知识上继续推进，把尚未闭合的可信度链条连接到公理与可检查的证明。

## 核心理念

数学研究不应该只保存“最后证明成功的答案”。失败的尝试、条件性结论、反例搜索和未完成的分支，也应该成为下一次推理可复用的知识。

OpenMath 将命题组织成**证明图**：节点表示命题，超边表示从多个前提到一个结论的推导。同一结论可以有多条路线。LLM 的工作是提出路线、寻找反例、调用工具、补齐引理，并提交可以被检查器验证的证明。

我们希望进一步建立统一的数学中间语言：将已有数学与科学知识表示为带类型、定义域、假设和来源的形式化对象；在适用的理论片段中计算规范形式，让不同写法的同一对象共享索引。新问题到来时，先查已有结论和证据，再决定继续证明什么。

## “可信度”具体是什么意思？

| 状态 | 含义 | 能否视为 100%？ |
| --- | --- | --- |
| 公理 `axiom` | 在当前理论中明确接受的起点 | 是，相对于该理论 |
| 已证明 `proven` | 检查器已验证，所需前提均已成立 | 是，相对于公理和检查器 |
| 猜想 `conjectured` | 有计算、实验或搜索支持，仍有证明缺口 | 否 |
| 未知 `unknown` | 尚无有效证明或支持信息 | 否 |

**100% 是“指定理论中的证明已闭合”，不是对现实世界的绝对保证。** 公理必须由使用方明确选择。一个带假设的证明只能证明“若假设成立，则结论成立”；要得到无条件结论，还需要证明或明确接受这些假设。

“长期没有找到反例”可以提供很强的研究线索，但其意义取决于搜索空间、覆盖范围与采样方法。当前原型将其记为 `supportScore`（搜索启发式），不会冒充命题为真的概率，也不会因试验次数增加自动升级为证明。未证明命题的 `confidence` 为 `null`。

## 当前可运行的原型

- **精确公式归一化**：使用 BigInt 将整数多项式展开为规范形式；识别交换、结合、分配律下的等价表达式。
- **上下文相关检索**：命题指纹包含语言版本、定义域、归一化版本和公理集合，防止跨理论错误复用。
- **多路线证明图**：支持多个候选推理路线，返回启发式得分和当前选中路线的待证明前提。
- **最小检查器**：验证多项式恒等式与 modus ponens（由 `P` 和 `P → Q` 推出 `Q`）。
- **防止循环自证**：从公理和已检查恒等式开始迭代，互相引用的未证明节点不能获得证明状态。
- **可运行示例与自动测试**：无需 API key、模型服务或第三方运行时依赖。

这是研究原型，并非通用定理证明器。尚未实现自然语言自动形式化、Lean 集成、科学知识库、量词推理、反例检查器和经过校准的可信度模型。当前检查器本身也未经形式化验证。

## 快速开始

需要 Node.js 22 或更高版本。

```sh
git clone https://github.com/zhuhaichao518/OpenMath.git
cd OpenMath
npm test
npm run demo
```

无需运行 `npm install`。示例展示：检索等价多项式恒等式、在显式公理下完成推理链，以及高支持度仍保留证明缺口。示例中的试验计数是明确标注的模拟数据。

```js
import { ProofGraph } from './src/index.js';

const x = ['var', 'x'];
const graph = new ProofGraph();
graph.add({
  id: 'double',
  statement: ['eq', ['add', x, x], ['mul', 2, x]]
});

console.log(graph.analyze('double').status); // proven
console.log(graph.lookup(['eq', ['sub', ['mul', 2, x], x], x]));
```

## 长期工作流

1. 将问题转换为带明确语义、定义域和假设的形式化命题，并核对翻译是否忠实。
2. 在支持的理论内归一化；利用索引检索已证明结果、条件性结果和历史尝试。
3. 展开多条证明路线，记录依赖关系和缺失引理。
4. 综合证据质量、证明缺口、搜索成本，选择下一步行动。
5. LLM 调用符号计算、反例搜索和形式化证明工具。
6. 检查器核验证书；证明闭合后，更新依赖该结果的链条。

## 为什么不直接把所有知识化成唯一“最简式”？

项目追求的是**在明确理论片段中的规范形式和可验证等价关系**。任意数学命题的语义等价，不能依赖一个保证终止、覆盖所有情况的万能化简器来解决。超出当前归一化范围时，应保存原式并寻找等价证书；检索不到相同指纹不意味着命题不等价。

科学模型还需要保留单位、适用条件、近似误差和实验来源。模型内部的数学证明，不会自动变成模型对现实世界的正确性证明。

## 与已有工作的关系

本项目与已有的 [OpenMath 标准](https://openmath.org/standard/)是独立项目，没有隶属关系。该标准描述数学对象的语义表示；未来可以探索适配它的符号体系。当前实验性 `OM-IR` 并不宣称兼容该标准。

正式证明验证计划对接 [Lean](https://lean-lang.org/)，其[公理与证明依赖说明](https://lean-lang.org/doc/reference/latest/Axioms/)也是本项目区分理论假设和证明状态的参考。归一化与不可判定性的边界可参阅 [Stanford Encyclopedia of Philosophy: Computability and Complexity](https://plato.stanford.edu/entries/computability/)。
